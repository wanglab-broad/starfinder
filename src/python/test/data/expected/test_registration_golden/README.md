# Expected values of `test_registration_golden.py`

`demons.npz` holds `displacement_zyx`, the float64 demons displacement field (8×32×32×3: Z, Y, X
and the ZYX components) of the translation → demons run of the golden fixture. The test compares it
with `rtol=1e-9`, `atol=1e-12` (docs/contributing.md, "Expected values and tolerances"). Before
W-574 the test compared the field's SHA-256 digest (`coordination_helpers.digest`) with a pin; the
registered uint16 images keep their digests and the translation stays exact.

They were generated by W-574 from Starfinder `3a4d2347548f8943176a2a1985ff428ebe95e69c`, the base
revision of W-574, exported and run as follows (on host GP099-29C, Intel Xeon Gold 6234, with the
locked environment `dev-s210-export-20261007T050852Z`: Python 3.12.12, NumPy 2.2.6, pandas 3.0.0,
SciPy 1.17.0, scikit-image 0.26.0, SimpleITK 2.5.3; one CPU and one numerical thread):

    git archive 3a4d2347548f8943176a2a1985ff428ebe95e69c src/python/starfinder src/python/test \
        src/python/pyproject.toml docs workflow | tar -x -C <export>
    cd <export>/src/python
    PYTHONPATH=<export>/src/python OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
        taskset -c 0 python generate_expected.py <checkout>/src/python/test/expected_values.py <output>

`generate_expected.py` is kept with the W-574 run records
(`starfinder_benchmark/runs/W-574/20261025T191325Z-3d9b138e/scripts/`). It computes every value with
the base revision's own test helpers and package code. A saved comparison on the same export
(`compare_expected.py` there) showed that these values, encoded as the tests encoded them before,
give each value the tests pinned before exactly. Nothing here is regenerated by the tests.
