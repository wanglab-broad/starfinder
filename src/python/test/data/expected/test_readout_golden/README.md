# Expected values of `test_readout_golden.py`

The explicit expected values of the readout golden test on its seeded fixture (W-279; W-573
replaced the SHA-256 digests pinned before):

* `extraction.npz`: the extracted tensor `values_<radius>` (float64 sums of uint16 pixels) and
  `valid_<radius>` for the radii (1, 2, 2) and (0, 1, 1);
* `pre_qc-<decoder>.csv`: the scored reads of `FOV.run` (`pre_qc`) of each decoder; without the
  score columns, the decoding table;
* `filtering-<decoder>-<filter>.csv`: the filtering table of the scored reads of `FOV.run` for the
  filters `default`, `bound` and `end_bases`; without the score columns, the filtering table of the
  decoding table;
* `candidates.csv`: the candidates table that `FOV.run` writes, with the background columns (the
  same for both decoders).

The tests compare the computed float64 columns (`COMPUTED_COLUMNS` and the `bg_*` and `noise_*`
columns of `test_readout_golden.py`) within the float64 tolerance of docs/contributing.md and every
other column, and the arrays, exactly. `test_readout_validation.py` (R6) and
`test_readout_deduplication.py` (R15, R17) compare with the same files.

They were generated by W-573 from Starfinder `3fe231f5ea981fa99d2239e7b78f83aadb09895b`, the base
revision of W-573, exported and run as follows (on host GP099-29C, Intel Xeon Gold 6234, with the
locked environment `dev-s210-export-20261007T050852Z`: Python 3.12.12, NumPy 2.2.6, pandas 3.0.0,
SciPy 1.17.0, scikit-image 0.26.0; one CPU and one numerical thread):

    git archive 3fe231f5ea981fa99d2239e7b78f83aadb09895b src/python/starfinder src/python/test \
        src/python/pyproject.toml | tar -x -C <export>
    cd <export>/src/python
    PYTHONPATH=<export>/src/python OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
        taskset -c 0 python generate_expected.py <checkout>/src/python/test/expected_values.py <output>

`generate_expected.py` is kept with the W-573 run records
(`starfinder_benchmark/runs/W-573/20261025T180422Z-c0ac8f32/scripts/`). It computes every value with
the base revision's own test helpers and package code and writes it with `write_csv` of
`test/expected_values.py`, which also defines the file format and the reader. A saved comparison on
the same export (`compare_expected.py` there) showed that these values, encoded as the tests encoded
them before (`table_digest`, `digest` or the SHA-256 of the file the checkpoint writer writes), give
each digest the tests pinned before exactly. Nothing here is regenerated by the tests.

`dtypes.json` records the dtype of every column of every CSV file; the CSV files hold floats in
`%.17g` and a missing value as `<NA>`.
